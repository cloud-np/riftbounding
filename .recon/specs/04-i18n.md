## 2. Message loading (simulator)

- Provider: next-intl (`createTranslator` on RSC payload messages; namespaces `broadcast`, `common`, `current`, `sim`).
- **English** = source catalogs shipped with the flight payload (RSC) — `playapp.rsc.txt`/`route_game.rsc.txt` contain one `"messages":{…}` blob; extracted verbatim to `i18n-en.json` (`ui` = 2179 `sim` leaves + 215 `common` + 1009 `current` + 154 `broadcast`). The marketing site's own catalog (extra namespaces `search/advanced/nav/play/playPage/card/sets/contact/theme/utility/web/errorBoundary`) is included as `siteMessages` in the same file (from `play.rsc.txt`).
- **Other locales** = precompiled next-intl catalogs in lazy chunks; keys are `key_<hash>` where the 7-char hash is derived from the key path and is **identical across locales** (strip `_<hash>` to get the source key):
  - fr: `0evbr82vl51g3.js` (module 851955) — 717 `exact` + 89 `patterns` + `parts`
  - ko: `3uxppa2k0kx93.js` (module 352317)
  - zh-CN: `1t3kr4xds6byf.js` (module 229067)
  Each file is a full standalone catalog (`{exact, patterns, parts}`) — missing keys fall back to EN.
- **Game-log sentences** are separate catalogs: EN templates are code (`0aed5y6vhcy22.js`, module 846015, `b(key,text)` + `g(key,/regex/,groups)` patterns), the other locales are JSON `{"sentence":{…}}` chunks: fr `0r12sly2zwo8g.js`, ko `0p4ahzekegpbg.js`, zh-CN `1wtthi75czt6u.js`. Extracted: 185 EN keys (67 literal + 118 pattern-marked), fr/ko/zh sentence maps.
- **Card text** (rules text, some flavor text) is per-locale JSON: fr `02bk-383zwes8.js` (203 KB, sets incl. RAD/VEN…), ko `3xwrnr9ftjnb3.js` (87 KB), zh-CN `1-gn975j0s9u2.js` (25 KB) and full `3ukxyvmzf6m-n.js` (442 KB). Locale manifests (`schemaVersion 2`, `{assetPathSegment, verificationStatus, publishedSets{set:[cardIDs]}}`): fr `1uw-ffl94kbzv.js`, ko `0euszzvixnn8j.js`, zh-CN `0z861aym8m0jw.js`.
- Card images: locale variant path `https://assets.riftatlas-workers.com/riftbound/cards/<assetPathSegment>/small-v2|original/<ID>.webp?v=<rev>`; `<html data-riftbound-card-asset-locale="en">` tracks the active card-art locale; missing translations fall back to EN text/art.
- Lazy-load map (dynamic imports) lives in `3lkda0iwi2gi6.js` (chunk→module table quoted in this repo's spec).

## 3. Switching

UI: `hub-locale-select` `<select aria-label="Language">` in the simulator header; `RiftboundLocaleToggle` (site) and `GlobalNotFoundLocaleToggle` (404) use the same component (`2smwag0o-c14m.js`). On change:
1. normalize the code; 2. set cookie `riftbound_locale=<code>; Path=/; Max-Age=31536000; SameSite=Lax` (+ `Domain=riftatlas.com` when host ends with `riftatlas.com`; + `Secure` on https); 3. `window.location.assign(localizedPath(pathname, search, hash))` — i.e. a hard navigation to the prefixed route (`/fr/...`). This means locale is both cookie- and path-derived; the middleware/app reads the path prefix first, cookie as fallback. `<option value>`s are `en`, `zh-CN`, `fr`, `ko` with `lang` attributes; disabled while pending.

Extraction quirks for a rebuild: locale UI catalogs are *compiled* (`exact`/`patterns`/`parts` ICU-compiled form with hash-suffixed keys); EN is *source* form. To re-key the localized catalogs to source keys, strip the `_<hash>` suffix (`signInToPlayOrSpectate_0uklrkq` → `signInToPlayOrSpectate`). EN sentence templates with `$pattern:true` are regex-parsed dynamic strings (`g()` in the chunk) — see chunk for the regex/group definitions.
