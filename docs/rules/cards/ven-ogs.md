# Vendetta (VEN) and Proving Grounds (OGS) card scripts — wave R3

Lane `ven-ogs`: the unscripted Vendetta and Proving Grounds names of `docs/cards-coverage.md`.
Scripts live in `packages/rules/src/cards/VEN/*.ts` and `packages/rules/src/cards/OGS/*.ts`
(one card per module); tests in `packages/rules/test/cards/ven-ogs/*.test.ts` (one behaviour
test per card, titled `[C:Card Name][R…]`).

## Conventions

- `src/cards/VEN/shared.ts` holds the lane's builders and `ven:*` conditions/effects:
  - `empower(cost)` — 827.1.c.1 "[Cost]: Empower this. Use only if not Empowered." (the
    precondition is a `requires`, rejected by `validateChoices`, 377.2.b);
  - `whileEmpowered(modifier)` / `conditional(condition, modifier)` — Dependent (828.1.c) and
    conditional (364.3.a) passives through the `conditional` modifier;
  - `notIntrinsic(keyword)` — the catalog lists keywords that only appear in reminder text or in a
    dependent ability (e.g. an [Empowered] keyword); the `value: 0` marker removes the printed
    instance (727.1.b) so only the granting ability applies;
  - `perCountCostReduction(...)` — "costs [1] less for each …": the cost layer sums fixed amounts,
    so one conditional -1 `cost` entry is registered per threshold. For "this ability costs …
    less" the entries also require the source to be on the board, so the card's own play cost
    from hand (366.2.a) is not reduced; the cost layer matches activations by source object, which
    is exact for cards whose only activated ability is the one reduced.
- [Empowered] triggered abilities are written with `condition: SELF_EMPOWERED` (828.1.c: active
  only while Empowered, checked at detection).
- "When I become [Empowered]" triggers on the `empower` event with the source as subject
  (442.2.a, 828.1.d).
- Choices that depend on the trigger event (e.g. "a battlefield I moved to or from") read the
  event from the chain item being finalized (`eventOf` in `shared.ts`), since 403.2 choices are
  made before resolution.

## [BUG] reproductions

Skipped tests in `packages/rules/test/cards/ven-ogs/bugs.test.ts` (unskip to verify a fix):

- **Expiration Step drops Empowered (317.2.c / 442.2).** `cleanup/cleanup.ts` `expire-this-turn`
  deletes every rules object without buffs/`baseMight`/counters/`grantedKeywords`/
  `grantedAbilities`/`controller`. Gear, legends and 0-Might units (Steel Paws) therefore lose
  `empowered` (and `keywordGrants`, `prevent`, `mightMods`, `paidAdditionalCost`) at the end of
  every turn; Empowered lasts until the object leaves the board. Affects every Empower gear/legend
  of this lane (Rage Amplifier, Tools of Empire, Platewyrm Egg, Jayce, Defender of Tomorrow, …)
  and Steel Paws.
- **Deflect values are charged as 1 (809.1.c / 809.2).** `play/additional-costs.ts`
  `deflectCosts` reads `cardKeywords`, i.e. the array form of `effectiveKeywords`, which returns
  bare names, so `keywordValue` counts 1: choosing a [Deflect 2] unit (Nasus, Ascended) costs
  [Rune] instead of [Rune][Rune].
- **Play restrictions on cards in hand are ignored (054.1).** `layers/restrictions.ts` `restrictionFor` reads board modifiers only, so Ol' Poro's "can't be played on your first, second or third turns" has no effect (`batch4-more.test.ts`).
- **Delayed replacement matchers ignore the creator's choices (359.3.f.3.a / 391.3).**
  `effects/ops/delayed.ts` `replace` stores `choices` and passes them to the replacing
  instructions, but `replacements/interceptor.ts` `matchesProposal` evaluates `matches` without
  them, so "the next time it dies this turn" with `subject: { targetRef: "target:0" }` never
  applies. Highlander works around it with `ven:with-bound` (the chosen id is frozen into the
  matcher as `obj:<id>`).
